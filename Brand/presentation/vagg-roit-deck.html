o que é

Um agregador de VPNs dentro da ROIT.

O VAGG é um servidor self-hosted que mantém túneis persistentes para todas as VPNs dos clientes. O consultor não instala mais nenhum cliente VPN específico — usa apenas a VPN ROIT (que já existe).

O fluxo do consultor

  1. Conecta na VPN ROIT (mesma de sempre)
  2. Abre o VAGG Client no notebook
  3. Vê os clientes liberados conforme política
  4. Acesso é instantâneo, sem segundo MFA

Princípios de design

  • Self-hosted ROIT — dados nunca saem da nossa rede
  • Sem MITM nos túneis — não inspeciona tráfego dos clientes
  • Não substitui a VPN ROIT — senta atrás dela
  • RBAC por construção — default-deny
  • Audit hash-chained — pronto pra LGPD

fluxo do pacote

Como o tráfego do consultor chega no servidor do cliente.

1 · Resolve DNS
Consultor faz ssh sap.cliente-energia.vpn.roit. DNS interno aponta para o VAGG.
2 · NAT virtual
VAGG retorna IP virtual 10.200.11.50. Cada cliente tem um /24 só dele no espaço virtual 10.200.0.0/16.
3 · Avalia política RBAC
O VAGG verifica: consultor tem policy ativa para Cliente Energia? Sim → rota liberada. Não → packet drop + audit event.
4 · Reescreve destino
iptables NETMAP traduz 10.200.11.50 → IP real do cliente 192.168.1.50.
5 · Encaminha via túnel
Marca de pacote roteia o tráfego para a interface ppp0 do container vagg-tunnel-cliente-energia.
6 · Resposta
Volta pelo caminho inverso com SNAT. Audit log registra a transação completa.
⚡
Overhead esperado: < 5ms vs conexão direta. Mas IPs sobrepostos entre clientes deixam de ser bug — viram only configuração.

controle de acesso · ponto-chave

Sem política, sem acesso. Default-deny.

Esse é o mecanismo mais importante para a ROIT — e o que dá conforto regulatório aos clientes.

Como funciona

  • Cada consultor é cadastrado uma única vez no painel VAGG
  • Admin atribui uma policy por par consultor × cliente
  • Sem policy ativa, o pacote NÃO sai do agregador — pacote é dropado e gera audit event
  • Revogação é instantânea: remover policy = perda imediata de acesso (próximo pacote já é negado)
  • Toda decisão (allow/deny) é registrada em audit log hash-chained

Por que isso importa

  • Onboarding de novo consultor: 1 clique por cliente que precisa acessar
  • Offboarding: revogação central, < 5s — em vez de remover de N VPNs
  • Auditoria do cliente final: "quem da ROIT acessou minha rede em Q3?" — relatório pronto
  • Compliance LGPD (Art. 37) — registro de operações já cumpre por construção
  • Defesa contratual: evidência técnica do RBAC nos contratos com clientes

consultores externos · regra obrigatória

Fora da ROIT? Conecte na VPN ROIT primeiro.

O VAGG não está exposto na internet — por design. Só quem está na rede da ROIT (pessoalmente ou via VPN corporativa) consegue alcançar o servidor.

Cenário do consultor remoto

  1. Consultor em casa, em coworking, em viagem
  2. Abre o cliente OpenVPN/Wireguard da ROIT — autentica com MFA
  3. Recebe IP da VPN corporativa ROIT
  4. Abre o VAGG Client → painel carrega normalmente
  5. Clientes liberados aparecem; rotas para redes dos clientes são aplicadas
🔒
Por que essa exigência: centraliza a autenticação corporativa em um único ponto (VPN ROIT com MFA), aproveita o controle já existente e evita expor o agregador para a internet pública.

O que o consultor NÃO precisa fazer

  • Instalar FortiClient
  • Instalar GlobalProtect
  • Cadastrar AnyConnect
  • Configurar Wireguard do cliente
  • Guardar senhas dos clientes
  • Lembrar de portas custom, gateways, certificados
  • Fazer push de Authenticator a cada reconexão

O que o consultor faz

  • 1ª vez: instala o VAGG Client (instalador .exe) e loga com credencial ROIT
  • Dia-a-dia: VPN ROIT + abre o VAGG Client; clientes liberados aparecem

VAGG client · windows

O lado do consultor — uma janela, três botões.

O que o consultor vê

Pequena aplicação nativa Windows (.exe instalável). Roda na bandeja do sistema. Mostra apenas os clientes liberados para aquele consultor — definidos pelas policies no servidor.

O que faz por baixo

  • Login com credencial ROIT (uma vez)
  • Sincroniza policies a cada ~30s
  • Aplica rotas no Windows automaticamente (Windows Service)
  • Bandeja com LED de status (verde / vermelho)
  • Botão "Atualizar rotas" para forçar resync manual

Zero VPN client específico

O consultor não instala FortiClient nem GlobalProtect — esses ficam apenas no servidor VAGG. No notebook só existe o VAGG Client.

situação atual

Onde estamos: fase de estabilização.

⚠
Pré-MVP em estabilização. O sistema já está conectando clientes reais em produção interna, mas ainda estamos endurecendo os caminhos de erro, instrumentação e UX. Quebras ocasionais são esperadas e tratadas no mesmo dia.

Funcionando hoje

  • FortiGate SSL VPN (5 clientes em produção interna)
  • SAML SSO com Azure AD via popup automático
  • MFA TOTP automatizado via seed cadastrado
  • Cliente Windows com tray + service de rotas
  • Audit log hash-chained
  • Watchdog de rotas (anti-hijack)

Em estabilização

  • GlobalProtect com HIP report (cliente construtora)
  • UX da extensão Chrome (SAML capture)
  • Tratamento de tunnel cair/voltar
  • Métricas e dashboards operacionais
  • Portal de transparência para cliente final

Roadmap pós-MVP

  • WireGuard, IPsec, OpenVPN UDP
  • JIT access via Slack
  • Time-bounded policies
  • Anomaly detection (acesso fora do padrão)
  • Cliente macOS / Linux

Como pedir suporte / reportar

Durante a estabilização, qualquer comportamento estranho — conexão pendurada, cliente sumindo da lista, erro inesperado no painel — favor reportar no canal interno com captura de tela e horário aproximado. Esses sinais aceleram a estabilização e ajudam a priorizar o que endurecer primeiro.
